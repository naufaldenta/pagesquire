# Security scope

For incident containment, lock/lease recovery, budget-preserving transcript erasure and retention boundaries, see the [operations runbook](docs/operations.md). The optional Node/PHP erasure APIs are trusted server integrations, not public endpoints or assistant capabilities.

PageSquire is not ready for unrestricted production action execution. The F2 alpha adds a server-owned PHP conversation engine, a Laravel endpoint, and a widget to the explicitly registered browser runtime. Automated checks use synthetic content and credentials, not live accounts.

Treat manifests, installed handlers, verifiers, and permission callbacks as trusted host configuration. Treat model calls and webpage text as untrusted input. Client checks do not replace server authorization, CSRF protection, endpoint abuse controls, or inference budgets.

Do not include passwords, tokens, form values, or other sensitive information in observations or evidence. Unknown handler errors are redacted by the runtime, but installed adapters are responsible for the evidence and error messages they deliberately return.

Provider requests transfer conversation text, approved capability metadata, and filtered page content to the configured vendor. Obtain appropriate consent and select a suitable retention/data policy. A visitor can type sensitive information into chat even when DOM observation excludes it. There is no default external telemetry.

Keep provider endpoints/models/keys in server configuration. Enable the Laravel route deliberately, define both gates, and use server-side sessions, a durable cache, atomic locks, CSRF, rate limits, infrastructure body limits and provider spending controls. Budget attempts are checkpointed before inference. A browser abort does not guarantee remote cancellation. Cache state contains transcripts; restrict access and configure expiry/secure transport.

Opt-in generic `ui.*` tools act on ordinary page controls inside the host's `canInteract` region; built-in risk tiers deny credential and payment forms and require approval for submissions and destructive-sounding controls. Review each site's region and tiers before enabling them ([details](docs/generic-actions.md)). Browser results are untrusted telemetry. They do not grant business permissions or prove server-side state changes. Consequential actions stay disabled unless the server engine opts in, the host authorizes the ID and the browser runtime has an approval prompt; each call then still needs a person's explicit approval, which is a confirmation step, not server authorization. See [WebMCP, approvals and WordPress Abilities](docs/webmcp-and-approval.md). Trusted handlers may still be unsafe or mislabel impact; review every installed capability. Prompt instructions cannot guarantee factual correctness or prevent all prompt injection.

Known boundaries: one conversation slot per session, no cross-tab coordination, no general transcript restoration, no production-host security audit, and no assistive-technology review yet. A bounded Sumopod smoke is recorded in [model evaluation](docs/model-evaluation.md); it is not a broad accuracy or prompt-injection benchmark. Full-document navigation continuation is opt-in, same-tab, short-lived, consumes minimal IDs/URL once and does not rerun the action. The local PHP/Node/Next.js demos are for localhost only and must not be deployed as public services.

F4 Node/native PHP endpoints require an explicitly configured public Origin, POST JSON, session-bound CSRF and host authorization. Internal/proxy Request URLs never determine the trusted origin. File stores require a private persistent local directory, single host and service-account ACLs. Multi-host/serverless deployments need a genuinely shared atomic durable store. Host session creation, global/principal/IP quotas, storage quotas, retention cleanup, safe lock recovery and edge connection limits remain deployment responsibilities. Per-session budgets are not currency caps. Node lock directories can remain after process termination; never break a lock without verifying its owner stopped. Custom transport/storage/auth implementations are trusted host code and must bound their own I/O.

Conversation files contain plaintext server-side transcripts/results. Keep them outside the web root, exclude them from source control/public backups and apply the host's retention and encryption-at-rest policy. Browser checkpoint IDs are not credentials or authorization, but are still readable by same-origin scripts; only deploy trusted scripts and keep CSP appropriate to the host.

Report vulnerabilities privately through [GitHub private vulnerability reporting](https://github.com/naufaldenta/pagesquire/security/advisories/new). Repository creation and enabled reporting were verified through GitHub's API on 2026-10-20; no fake report was submitted. Include affected version/commit, a minimal synthetic reproduction, impact and suggested mitigation if available. Never post exploit details, live credentials or visitor data in public issues. If GitHub reporting is unavailable, open only a neutral request for a private contact, without sensitive details; no fallback email is configured.

No published release currently has a security-support commitment. The only candidate is `0.1.0-beta.0`; other versions and production deployments are unsupported/unverified. Review the [compatibility matrix](docs/compatibility.md). Security fixes will be documented in English release notes with affected/fixed versions once a reporting and release process is operational; no response-time or backport guarantee is established.

## WordPress alpha

The plugin is disabled by default. `manage_options` plus a valid WordPress REST nonce gates administration; exact Origin, explicit access/consent, current selected-page inspections, signed HttpOnly sessions and session-bound CSRF gate chat. A public WordPress nonce is not anonymous authorization or abuse prevention. Explicit public mode exposes a paid service to strangers: configure host/WAF protections and provider spending limits before opting in. Browser inspection reports are administrator-reviewed telemetry, not attestation or permission.

Global database-backed limits count requests across cookies and provider attempts across sessions (including failures). Per-minute site/IP request limits and the daily provider budget use lock-free conditional `UPDATE` counters, so concurrent visitors do not collide on a shared lock; only session issuance serializes its registry, with short bounded retries. They are not currency caps. Salted IP hashes use the direct peer address, not untrusted forwarded headers. Conversation state and encrypted keys are non-autoload options; this is not database encryption. Salt rotation invalidates keys and sessions. Session cleanup is traffic-driven after expiry plus two minutes, so idle sites retain options. Deactivation/uninstallation preserves data for recovery; permanent removal and backup retention remain administrator responsibilities.

Atomic option locks fail closed after worker termination. Disable the plugin, drain every assistant worker and back up before removing only confirmed stranded lock options. Never automatically steal locks or erase budget records as recovery. A coherent WordPress options cache and single writable database are required; distributed failover/multisite are not certified. Exclude selected pages and assistant REST endpoints from shared caches. See the [operational guide](packages/wordpress/README.md).

Configuration import accepts only current-origin built-in root/adapter IDs, never executable code, custom selectors or business permissions. Export excludes raw content/HTML/block attributes, protected/private posts, users, values, keys and source; public titles/URLs still need owner review. During chat, selected public metadata, visitor messages and filtered visible text/labels reach the configured external HTTPS provider. Do not enable on sensitive pages. Safe WordPress HTTP transport rejects unsafe targets/redirects and bounds responses; third-party host HTTP hooks are trusted server code. No live vendor is selected automatically. Test fixtures and their synthetic authentication endpoints must never be deployed.

## Onboarding CLI

Static discovery/validation do not execute website modules, hooks or route commands. They exclude known secret/private/config/build paths and export metadata only. Metadata, stable IDs, paths and source digests can still be sensitive; this is not a DLP guarantee. Review reports and generated skills before sharing them with a coding agent. Scan evidence never grants action permissions.

Optional DOM observation renders explicitly approved staging pages in an isolated browser; page JavaScript runs. Network restrictions block foreign requests, fetch/XHR, mutating methods, service workers, WebSockets, downloads and unapproved navigation. Rendering still issues allowed same-origin GET/HEAD requests, which are not universally side-effect free. Do not scan mutating GET routes or untrusted/production sites without appropriate authorization. No login state is imported. Hidden/authenticated/dynamic states may remain unobserved.

The CLI refuses symlinks/junctions and file conflicts. These controls do not protect against a concurrent hostile process modifying the local filesystem; use a trusted checkout. `validate --compile` writes development artifacts without executing adapters, but generated bindings will import those modules when the host uses them. Review their actual effects and postconditions. A static pass always reports runtimeVerified=false. Coding-agent instructions are guidance, not an enforcement boundary, and public deployment/provider activation requires separate review.
