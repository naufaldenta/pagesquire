# Languages

PageSquire ships English and Indonesian copy for everything it shows on its own, as opposed to what the model writes:

- the widget (labels, buttons, status line, action progress and recovery guidance)
- the approval prompt
- the guided tour controls
- transport and client error messages
- the engine's fixed replies (cancelled, not verified, limits, refused typing, unconfirmed completion)

The model's own answers follow the visitor's language as instructed by the host.

## Browser

Components default to `locale: 'auto'`. This follows `<html lang>`: `id`/`id-ID` (and the legacy `in`) selects Indonesian, and any other tag selects English. Pass `locale: 'en' | 'id'` to force a language, and `messages` to override individual keys:

```js
import {
  AssistantClient,
  createHttpTransport,
  createApprovalPrompt,
  createVisitorPrompt,
  mountWidget,
} from '@pagesquire/client';

const options = {
  locale: 'id',
  messages: { 'widget.placeholder': 'Coba “Ringkas artikel ini”' },
};
mountWidget(host, client, options);
createHttpTransport({ endpoint, baseUrl, csrfToken, ...options });
new AssistantClient({ runtime, transport, ...options });
createApprovalPrompt(host, options);
createVisitorPrompt(host, options);
new GuidedTour({ observer, driver, ...options });
```

- All keys are listed in `en` (exported from `@pagesquire/client`), and `MessageKey` types them.
- `{name}` placeholders, such as `{stage}`, `{capability}`, `{emotion}` and `{text}`, are filled by the component.
- `resolveMessages(options, document)` returns the final set.
- `describeActionProgress(event, messages)` localizes custom progress UIs.

For another language, pass a complete `messages` set. Missing keys fall back to the selected built-in locale.

The one-tag embed accepts `data-locale="en|id|auto"`. The WordPress plugin uses the configured reply language or, when that is automatic, the site locale.

Developer surfaces stay in English: the capability inspector, the trace viewer and exception messages meant for integrators.

## Server

The fixed replies of the Node and PHP engines are set by `locale` (`'en'` by default, or `'id'`).

| Host      | How to set it                                   |
| --------- | ----------------------------------------------- |
| Node      | `new ConversationEngine({ ..., locale: 'id' })` |
| PHP       | the `locale: 'id'` constructor argument         |
| Laravel   | `PAGESQUIRE_LOCALE=id`                          |
| WordPress | follows the plugin language or the site locale  |

`ENGINE_TEXT` (Node) and `ConversationEngine::TEXT` (PHP) hold the strings. Unsupported locales are rejected at construction.
